# AEGIS SOC | Repair and Installation Guide

## What was broken in the uploaded ZIP

The uploaded `aegis-soc.zip` had all the main Python modules but **no `database/aegis.db`**. The FastAPI dashboard endpoint therefore returned `503: database not found`. It also included `app/pages/01_Live_Operations.py.bak.py`, which Streamlit still recognized as a separate page because its filename ends in `.py`. The runtime API dropped Ollama model metadata, and the repository's `alert_id` investigation filter assumed a non-existent column.

## Repairs included

1. Rebuilt the SQLite native schema directly from the actual SQL reads/writes in `agents/multi_agent_orchestrator.py`, `agents/triage_agent.py`, and the dashboard services (`database/schema.sql`).
2. Included a clean database (`database/aegis.db`) with eight synthetic case records. It starts with **zero investigations**, zero model outputs, zero native audit events, and zero decisions. These must be generated by real usage; the old historical records were not supplied.
3. Added `scripts/initialize_database.py` to safely repair or initialize missing tables/cases in the future (existing rows are preserved).
4. Fixed `database/repository.py` for correct investigation ordering and joins to `cases.alert_id`.
5. Fixed `api/aegis_api.py` so model metadata returned to the dashboard and n8n reflects actual orchestrator results.
6. Added investigation IDs to the orchestrator's native audit rows, and kept persisted agent evidence.
7. Adjusted recorded analyst approval/rejection and escalation resolution to update the parent case status while retaining the historical investigation decision.
8. Moved the obsolete extra Streamlit page backup out of `app/pages` to `legacy/`, while retaining `app/app.py` as the sole main frontend.
9. Added a macOS launcher and an offline full-stack smoke test.

## Important: how to install without losing your setup

- Merge the contents of this ZIP into your existing `~/Desktop/aegis-soc` folder. **Do not delete the original folder first.**
- The ZIP omits `.venv/` (a macOS virtual environment cannot be safely shipped from another computer), `.git/`, `.env`, n8n Docker volumes, and generated caches.
- The ZIP contains a fresh `database/aegis.db` because yours was missing. If you later find the original, back up both files and restore the original only after checking it has a compatible table structure. **Do not overwrite recovered investigation history with the demo database.**
- Your existing n8n workflows remain in Docker's persistent volume. No n8n export was available in the uploaded file, so none was fabricated.
- `app/app.py` is the updated single-file UI you supplied in your ZIP. The visual layout was retained, not replaced with a simpler frontend.

## Start services

**Option A:** Double-click `START_AEGIS_MAC.command`. If macOS blocks execution, right-click > Open, or use Option B.

**Option B:** Two Terminal windows:

```bash
cd ~/Desktop/aegis-soc
source .venv/bin/activate
python -m uvicorn api.dashboard_api:app --host 0.0.0.0 --port 8000
```

```bash
cd ~/Desktop/aegis-soc
source .venv/bin/activate
python -m streamlit run app/app.py
```

If you see "address already in use" on port 8000, stop the **old** FastAPI server in its Terminal (Ctrl+C). Do not start two servers on the same port. If the Streamlit port is occupied, Streamlit may choose port 8502 or 8503: use the URL printed by Streamlit.

Ollama must be running for real inference (`open -a Ollama` on macOS). `qwen3:8b` must be installed (`ollama list`). Docker and n8n are optional when the Streamlit user selects **Direct FastAPI**. For **Governed n8n workflow** mode, publish/activate the n8n workflow and enter its real production URL in the Streamlit sidebar (usually `/webhook/aegis-triage`, not `/webhook-test/aegis-triage`). The actual n8n workflow wasn't included in the uploaded folder.

## Database repair if missing again

```bash
cd ~/Desktop/aegis-soc
source .venv/bin/activate
python -m scripts.initialize_database
python -m scripts.inspect_database
```

The initializer doesn't clear case records or change prior investigations. Backup the database first if working with an existing instance.

## Evaluation

In the Model Lab, install three model IDs listed in `evaluation/model_registry.json` and then run the comparison. A full run needs three installed open-weight Ollama models; `qwen3:8b` was previously installed. No evaluation numbers are pre-filled. The benchmark measures triage classification and latency only, not the entire governance engine.

## Safety boundaries

Use only synthetic alerts and local trusted networks. API access is not authenticated. Analyst identifiers are form labels, not user authentication. Do not deploy this build to a public IP address or connect real enforcement actions.
